## 套餐里的“2核”到底是什么意思

搬瓦工的 CPU 有两套数字：套餐介绍里写的核数，和服务条款里写的一小时平均上限，两者说的是不同的事。

核数是峰值。你的 VPS 可以在短时间内把 CPU 跑到 100%，调用方案标注的全部核心，不会因为瞬时占用高就触发限制。一小时平均上限才是长期约束：一个小时内平均下来的 CPU 用量，不能超过套餐规定值。

以最便宜的 KVM 套餐（$49.99/年）为例，它标着 2 核，限制却是“1 个 CPU 核心的 50%”。意思是：两个核心可以短时间同时跑，但一小时平均用量不能超过半个核心，并非每个核心都能长期保持 50%。

为什么要这么设计？一台物理服务器上跑着几十台 VPS，某个用户的程序持续吃满 CPU，同机其他人的服务器就会变慢，商家必须给每个套餐划上限。搬瓦工的产品页不显示这些数字——套餐按硬盘和内存命名，核数只是峰值参考——具体限制写在服务条款里。这也是很多人买完才发现“2 核跑不满”的原因。

## CPU 超限后会发生什么：限速而非停机

超过一小时平均上限后，搬瓦工不会直接暂停或关闭你的 VPS。实际发生的是：

- VPS 继续正常运行
- 系统自动把这台 VPS 可用的 CPU 资源压到套餐规定的水平
- 用量降回套餐范围后，限制自动解除
- 触发限制时，KiwiVM 控制面板首页会显示 high CPU usage 提示

对低负载网站来说，这套机制几乎无感。但如果服务器正在压缩文件、编译程序或处理高并发请求，被限速之后速度下降会很明显。

遇到限制提示，先判断原因：只是临时跑了一个吃 CPU 的脚本，等一两个小时用量回落，限制会自动解除；如果长期都贴着上限跑，说明套餐已经不够用，升级高配套餐比反复被限速省心。

## 怎么查看 CPU 用量和是否被限速

两个工具配合用：htop 看实时占用，KiwiVM 看有没有触发限制。

在搬瓦工 VPS 里安装 htop：

bash
# Debian / Ubuntu
apt update && apt install -y htop

# Rocky Linux / AlmaLinux / CentOS Stream
dnf install -y epel-release
dnf install -y htop


SSH 里输入 `htop` 回车，重点看三块：顶部的进度条是每个 CPU 核心的实时使用率；右上角 Load average 是过去 1、5、15 分钟的平均负载；下面的进程列表能定位到底哪个程序在吃 CPU。

这里有个容易忽略的点：htop 显示的是实时状态，而搬瓦工官方算的是一小时平均值。htop 上偶尔飙红不代表会触发限制，反过来，你也没法从 htop 直接读出一小时平均是多少。判断是否已经被限速，去 KiwiVM 控制面板首页看有没有 high CPU usage 提示最直接，它的详细统计页里也有历史 CPU 使用图表。

**CPU 被限制后多久恢复？**

**搬瓦工的带宽是独享的吗？**

带宽属于共享带宽。在售方案起步 1Gbps，CN2 GIA-E 套餐 2.5Gbps 起步，DC6 CN2 GIA 和日本软银机房最高有 10Gbps。在这个价位的 VPS 上，带宽独享基本不存在，关注实际线路质量比盯着标注带宽更有意义。
